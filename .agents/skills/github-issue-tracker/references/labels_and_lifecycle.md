## 1. Схема жизненного цикла задачи

GitHub Issues имеет два базовых состояния:
- `Open` (Открыто)
- `Closed` (Закрыто)

В связке с GitHub Projects используется расширенный процесс (Kanban):
1. **Backlog** — Первичный сбор идей, гипотез и долгосрочных планов.
2. **Todo** — Отобранные в спринт/веху задачи, готовые к взятию в работу.
3. **In Progress** — Назначен исполнитель (человек или AI-агент), создана ветка `fix/...` или `feat/...`.
4. **Review / Testing** — Открыт Pull Request со связкой `Fixes #<number>`, запущены тесты `pytest`.
5. **Done** — PR слит (merge) в `main`, Issue автоматически закрыт.

## 2. Стандартные метки (Labels)

### Типы задач (Issue Type)
- `bug` — обнаруженные дефекты, падения или сбои в логике.
- `feature` — разработка новой функциональности с нуля.
- `enhancement` — улучшение или оптимизация существующего кода.
- `documentation` — обновление руководств, docstrings и README.
- `refactoring` — структурная очистка кода без изменения внешнего поведения.
- `research` — исследовательские задачи, бенчмарки и архитектурный дизайн.

### Приоритеты (Priority)
- `priority:critical` — критический сбой, блокирующий работу системы.
- `priority:high` — важная задача с высоким приоритетом выполнения.
- `priority:medium` — стандартный рабочий приоритет.
- `priority:low` — второстепенные доработки или косметические исправления.

### Компоненты AI-TC (Components)
- `component:telemetry` — сбор системных метрик, мониторинг температур и процессов.
- `component:network` — адаптеры, открытые порты, захват трафика (tshark).
- `component:windows` — службы ОС, дисковые накопители, реестр, SafeOps.
- `component:gui` — WebGUI интерфейсы, модальные окна, темы оформления.
- `component:ai` — LLM-провайдеры, ReAct агенты, RAG и промпты.
- `component:mcp` — Model Context Protocol серверы и интеграции.
- `component:core` — ядро, конфигурация, логирование и утилиты.
