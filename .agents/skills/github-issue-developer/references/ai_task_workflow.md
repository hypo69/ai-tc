## 1. Концепция: GitHub Issue как техническое задание (ТЗ) для AI

В проекте AI-TC задачи GitHub Issues используются не просто как трекер дефектов, а как **централизованное Task API** для взаимодействия с автономными AI-агентами разработки.

### 9-шаговый цикл автономной разработки:
1. **Регистрация задачи:** Создание Issue с описанием требуемой функциональности или ошибки по шаблону.
2. **Получение ТЗ агентом:** AI-агент считывает Issue, парсит требования, компоненты и критерии приёмки (`AITaskPlan`).
3. **Аудит архитектуры:** Агент исследует существующий стек в `apps/` и `src/` в соответствии с принципами `REUSE.md`.
4. **Формирование TDD плана:** Определение тестовых сценариев и списка изменяемых файлов.
5. **Изоляция в Git-ветке:** Создание ветки вида `fix/<number>-<slug>` или `feat/<number>-<slug>`.
6. **Реализация изменений:** Написание чистого кода строго по стандартам `GEMINI.md` (до 500 строк, русские docstrings, фиксация `Updated:` в шапке).
7. **Тестирование (TDD):** Запуск и успешное прохождение тестов (`pytest`).
8. **Создание Pull Request:** Открытие PR с обязательной связкой `Fixes #<number>` или `Closes #<number>`.
9. **Автоматическое закрытие:** Слияние PR в `main` автоматически закрывает Issue на GitHub.

---

## 2. Ключевые слова закрытия (Closing Keywords)
GitHub поддерживает следующие директивы в описании Pull Request:
- `Fixes #125` (рекомендуется для `bug`)
- `Closes #125` (рекомендуется для `feature`, `enhancement`)
- `Resolves #125` (для исследований и архитектурных задач)
